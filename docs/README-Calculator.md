# Калькулятор мобильности ПО в Unity

## Запуск

Откройте проект `Lab2` в Unity **6000.2.14f1**. Откройте сцену `Assets/Scenes/MobilityCalculator.unity` и нажмите Play. Если сцена ещё не создана, выберите **Mobility → 1. Prepare calculator scene**. Для исходной `SampleScene` калькулятор также запускается автоматически в Play.

Готовая Windows-сборка, когда сборка успешно выполнена: `Builds/Windows/MobilityCalculator.exe`.

## Работа с калькулятором

1. На экране **Параметры** задайте 16 начальных значений и положительные нормировочные параметры sᵢ. Интервал по умолчанию 0…1, шаг 0.001. Допускается точка или запятая в десятичных числах. Максимум 20 000 шагов.
   Кнопка **Случайные значения** над таблицей заполняет все 16 uᵢ(t₀) числами от 0 до 1 (три знака после запятой). Масштабы sᵢ и остальные настройки сохраняются; после заполнения нажмите **Рассчитать**.
2. Ниже выберите изменяемую характеристику и влияющую характеристику, чтобы настроить функцию конкретной связи. Общая форма: **a·x³ + b·x² + c·x + d**. Линейная функция имеет a=b=0, квадратичная — a=0; это единая система обозначения коэффициентов для всех степеней.
3. В **Матрице связей** нажимайте ячейки: 0 → +1 → −1 → 0. Столбец влияет на строку. Диагональ заблокирована. Подсказки расшифровывают номера.
4. В **Возмущениях** раскрывайте F1–F6 и задавайте коэффициенты **a·t³ + b·t² + c·t + d**. График всех факторов появляется после расчёта ниже редактора функций; при необходимости прокрутите экран.
5. Нажмите **Рассчитать**. На экране **Динамика** доступны все 16 линий, отдельные флажки и быстрый выбор качеств или дефектов. Наведение показывает время и интерполированные значения первых четырёх включённых линий.
6. В **Срезах времени** выберите начало, четверть, половину, три четверти или конец интервала. Синяя линия — начало, оранжевая — выбранное состояние. Ниже приведены точные числовые значения. У всех срезов одна шкала.
7. В **Модели и уравнениях** показаны определения и уравнения для текущей, в том числе отредактированной матрицы.

Изменение данных сбрасывает предыдущие результаты. Неверный текст выделяется красным; нулевые/отрицательные масштабы и неверный временной интервал отклоняются при расчёте. Кнопка **Сбросить** восстанавливает исходный сценарий. Параметры сохраняются при переключении экранов, но не между запусками приложения.

## Математическая интерпретация

См. `MobilityModel.md` — исходная матрица, определения, развёрнутые уравнения и допущения. Нумерация и названия подтверждены таблицей 2.1 диссертации, с. 99, 100, 106; матрица составлена для учебной задачи. u6 и u29–u33 растут при улучшении качества; u126–u135 растут при усилении дефекта.

Это нелинейная модель совместного действия факторов, а не линейная система Au+BF. Положительный и отрицательный темпы — произведения функций внутренних связей, умноженные на суммы соответствующих внешних факторов. Нет внутренних связей — внутреннее произведение 1; нет внешних — внешний множитель 1; полностью отсутствующий член 0.

F4–F6 исходно имеют нулевые столбцы и не влияют на u. Можно включить их вручную. Никакого скрытого ограничения значений до [0,1] нет. Отрицательные функции и выход показателей за [0,1] сопровождаются сообщением. При отрицательных значениях лепестковая диаграмма использует смещение шкалы: центр — минимум, а не ноль. Максимальная допустимая численная величина — 10¹².

Демонстрационные параметры не являются измерениями реального ПО. Численные результаты не следует трактовать как вероятности или подтверждённый прогноз.

## Онлайн-версия WebGL

WebGL Build Support установлен для Unity 6000.2.14f1. Готовая браузерная сборка находится в `Builds/WebGL`.

1. Для локального запуска дважды нажмите `Lab2/Open-WebGL.cmd`. Откроется браузер по адресу **http://127.0.0.1:8765/**. Окно сервера нужно оставить открытым; Ctrl+C останавливает сервер. Запуск использует установленный Python 3 (на этом компьютере — встроенный runtime Codex).
2. Для повторной сборки выберите **Mobility → 4. Build WebGL**. Сжатие отключено, чтобы не требовать специальных серверных заголовков.
3. Для размещения в интернете загрузите **всё содержимое** `Builds/WebGL` на статический HTTP(S)-хостинг, включая `index.html`, `Build` и `TemplateData`. Для `.wasm` сервер должен возвращать `application/wasm`. Открытие `index.html` через `file://` не поддерживается.

Вычисления выполняются локально в Unity внутри браузера; серверный API и отправка исходных данных не нужны. Адрес 127.0.0.1 доступен только на вашем компьютере. Публикация на внешнем хостинге не выполнялась.

## Проверки и сборка

- `Tests/run-core-tests.ps1` — самостоятельные тесты C# без запуска Unity: аналитические решения, порядок сходимости, шаг, интерполяция, матрица, отключённые возмущения, базовый сценарий.
- **Mobility → 2. Verify model and interface** — создание экранов и проверка неверного ввода средствами Unity. Отчёт: `TestResults/unity-verification.txt`.
- **Mobility → 3. Build Windows** — сборка в `Builds/Windows`, отчёт в `TestResults/build-StandaloneWindows64.txt`.
- Параметр запуска Windows-приложения `-mobilitySmoke` автоматически выполняет расчёт, сохраняет снимки шести экранов в `SmokeCaptures` рядом с exe и завершает приложение. Это проверка отрисовки, а не замена проверки мышью.

В редакторе также поддержана одноразовая очередь для локальной автоматизации: текстовый файл `Temp/mobility-command.txt` со значением `setup`, `verify`, `windows` или `webgl`. Выполняется только вне Play и компиляции, после чего файл запроса удаляется.
