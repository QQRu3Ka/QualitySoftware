# Модель мобильности ПО u6

Статус: модель согласована пользователем 21.10.2026 и реализована в проекте Lab2. Инструкция запуска — README-Calculator.md. WebGL-сборка создана и проверена в Chrome; локальный запуск — Open-WebGL.cmd.

## Источники и границы модели

Названия взяты из таблицы 2.1 диссертации «Дисертация_All_версия_в_печатьянварь_2018_2.pdf»: u6 — с. 99, u29–u33 — с. 100, u126–u135 — с. 106. Формулировки сохранены. Состав переменных ограничен заданием пользователя; u136 и u137 не включены.

Документ «Качество ПО.docx» задаёт пример знаковой матрицы, нелинейных уравнений с произведениями функций влияния, шести внешних факторов и графиков. На с. 145 и 149–151 диссертации описаны разложение темпов на произведения функций, построение уравнений по матрице и экспертный выбор связей. Матрица для мобильности ниже составлена для этой работы: она не скопирована из диссертации и не является нормативной матрицей ISO.

### Обоснование ненулевых связей

- u29–u33 положительно влияют на общую мобильность; дефекты u126–u135 влияют отрицательно.
- u126–u128 относятся к адаптируемости; u129–u132 — к установке; u133 — к сосуществованию; u134 — к взаимозаменяемости; u135 — к согласованности подсистем по протоколам.
- Согласованность подсистем облегчает адаптацию, установку, совместную работу и замену. Адаптация облегчает установку, совместную работу и замену; установка и совместная работа облегчают замену.
- Улучшение соответствующей подхарактеристики трактуется как результат работ по устранению её дефектов, поэтому задана обратная отрицательная связь. Это отдельное модельное допущение, а не вывод из одного лишь дерева классификации.
- Ограничения адаптации могут усиливать несоответствие требованиям и ошибки; несоответствие требованиям может усиливать ошибки.
- Повышенные требования к квалификации и недостаточная автоматизация могут увеличивать трудоёмкость подготовки и время установки; трудоёмкость подготовки также увеличивает время установки.

### Внешние факторы

Сохранены названия факторов из примера:

1. F1 — опыт разработчиков программного комплекса.
2. F2 — опыт работы эксплуатационного персонала.
3. F3 — трудоёмкость разработки программного обеспечения.
4. F4 — курс рубля по отношению к доллару.
5. F5 — деловая репутация разработчиков программного комплекса.
6. F6 — деловая репутация организации, в которой эксплуатируется программный комплекс.

В базовом сценарии F1 и F2 усиливают положительные изменения качеств и устранение дефектов; F3 усиливает ухудшение качеств и рост дефектов. Это экспертное допущение. Для F4–F6 влияние равно нулю: прямые причинные связи для заданной задачи не обоснованы. Эти факторы остаются доступными в интерфейсе и на графике; изменение их коэффициентов без изменения матрицы не влияет на траектории u.

## Система дифференциальных уравнений

Как в примере, используется разность двух произведений функций влияния с внешними множителями. Упрощённая запись g_j означает f(u_j(t)); в программной модели для каждой ненулевой связи допустимо задать отдельную функцию f_ij. Обозначим E(t)=F1(t)+F2(t), C(t)=F3(t).

Для i из {6,29,30,31,32,33}:

$$\dot u_i=\frac{E(t)\prod_{j:a_{ij}=1}f_{ij}(u_j)-C(t)\prod_{j:a_{ij}=-1}f_{ij}(u_j)}{s_i}.$$

Для i из {126,…,135}:

$$\dot u_i=\frac{C(t)\prod_{j:a_{ij}=1}f_{ij}(u_j)-E(t)\prod_{j:a_{ij}=-1}f_{ij}(u_j)}{s_i}.$$

s_i>0 — постоянный нормировочный параметр, аналог u_i* из примера; это НЕ текущее значение u_i(t). В диссертации (с. 151) такой знаменатель определяется как максимальное значение показателя в выбранной шкале. Для демонстрационного сценария ниже значение 10 задаётся отдельно как условный масштаб; для предметной калибровки его необходимо согласовать со шкалой исходных данных. Произведение по пустому множеству равно 1: в соответствующем члене действует только внешний фактор. При отключении всех внешних связей соответствующий внешний множитель принимается равным 1; если у члена нет ни внутренних, ни внешних связей, член равен 0. В приведённой матрице каждый член имеет внешние связи.

Развёрнутая система для общей функции f:

- du6/dt = [(g29 · g30 · g31 · g32 · g33) · E − (g126 · g127 · g128 · g129 · g130 · g131 · g132 · g133 · g134 · g135) · C] / s6.
- du29/dt = [(g33) · E − (g126 · g127 · g128) · C] / s29.
- du30/dt = [(g29 · g33) · E − (g129 · g130 · g131 · g132) · C] / s30.
- du31/dt = [(g29 · g33) · E − (g133) · C] / s31.
- du32/dt = [(g29 · g30 · g31 · g33) · E − (g134) · C] / s32.
- du33/dt = [(1) · E − (g135) · C] / s33.
- du126/dt = [(g127 · g128) · C − (g29) · E] / s126.
- du127/dt = [(g128) · C − (g29 · g33) · E] / s127.
- du128/dt = [(1) · C − (g29) · E] / s128.
- du129/dt = [(1) · C − (g30) · E] / s129.
- du130/dt = [(g129 · g131) · C − (g30) · E] / s130.
- du131/dt = [(1) · C − (g30) · E] / s131.
- du132/dt = [(g129 · g130 · g131) · C − (g30) · E] / s132.
- du133/dt = [(1) · C − (g31) · E] / s133.
- du134/dt = [(1) · C − (g32) · E] / s134.
- du135/dt = [(1) · C − (g33) · E] / s135.

### Функции и начальные условия

Для каждой ненулевой связи предлагается выбор: f(x)=a·x+b; f(x)=a·x²+b·x+c; f(x)=a·x³+b·x²+c·x+d. Знаки матрицы имеют смысл положительного/отрицательного влияния при неотрицательных значениях функций; для интерпретации как монотонного влияния функции также должны быть неубывающими на исследуемом диапазоне.

Начальный демонстрационный сценарий (собственные параметры, не данные диссертации): u_i(0)=0.5; s_i=10; f_ij(x)=x; t∈[0,1]; шаг h=0.001. F1=1+t²; F2=0.5; F3=0.2; F4=2t−1; F5=0.3; F6=0.4. Все параметры редактируются.

Решение: метод Рунге–Кутты 4-го порядка; последний шаг сокращается до конца интервала. NaN, бесконечность и превышение численного порога прерывают расчёт с сообщением. Значения вне [0,1] отображаются без скрытого обрезания с предупреждением о границах интерпретации. Для сравнительных диаграмм используется единая шкала, включая отрицательные значения.

### Ограничения

Произведение отрицательных факторов описывает их совместное действие: ноль любого множителя обнуляет весь член. Это выбранная по аналогии с примером структура, а не универсальное правило накопления дефектов. Для независимого накопления влияний потребовалась бы другая, аддитивная модель. Численные параметры нуждаются в экспертной настройке или калибровке; демонстрационный расчёт не является прогнозом реального продукта.

## Проект интерфейса Unity

Разработка в существующем проекте Lab2, Unity 6000.2.14f1. Все элементы интерфейса и графики рисуются внутри Unity. Целевая онлайн-поставка — WebGL; доступность модуля сборки и возможность публикации проверяются на этапе реализации.

1. «Параметры»: 16 начальных значений и масштабов s_i, интервал, шаг, редактор функций влияния, кнопки расчёта и сброса.
2. «Матрица»: таблица A и B с переключением −1/0/+1, подсказки с полными названиями.
3. «Возмущения»: редактор шести функций и общий график F1–F6.
4. «Динамика»: графики u_i(t), легенда и включение/выключение линий.
5. «Срезы»: лепестковая диаграмма с начальным и выбранным состоянием, моменты 0, T/4, T/2, 3T/4, T; таблица точных значений. Метки осей — номера u, полные названия — в легенде.
6. «Модель»: расшифровка переменных, источник, текущие уравнения и обозначение экспертных допущений.

Рекомендуемый подход: отдельный вычислительный модуль C# + Unity UI Toolkit + отрисовка графиков средствами Unity. Альтернатива — Unity Canvas/uGUI: удобна для ручной сборки сцены, но требует больше настройки элементов. Внешний веб-интерфейс не нужен.
